생성 코드의 핵심 계산 정확성 평가 — 계획 3판 (Codex 계획 검토 최초 5건 + 재검토 2건 반영)

질문을 다시 정함
- 주 질문: "실행 검사를 거쳐 실행되게 된 최종 코드(#60 exec 조건 최종본)는 논문의 핵심 계산을 맞게 하는가?"
- 보조 관찰: 최초본 → exec 최종본의 전이. 원자료 확인 결과(2026-11-07) 세 논문 모두 control 최종본 = 최초본이고 실행 시 오류다.
  따라서 control과의 '수치 정확도 비교'는 하지 않는다. control·최초본은 이번 부분 계산도 실행 불가인지만 새로 확인해 분류한다
  (주장 가능: "실행 불가 → 기준값 산출 가능/일치"까지. "수치 오차가 줄었다"는 주장하지 않는다)

대상 고정 (평가 전, 코드 해시를 기록)
- AVQ-Attention: main_9.json, exec 조건 2회차(최종) / 1회차(=control 최종)
- Explicit Dropout: pilot_explicit_dropout.json, exec 3회차(최종) / 1회차(=control 최종)
- Rotated LoRA: rerun_3.json(검사 규칙 2판, 최초 코드부터 새로 생성), exec 2회차(최종) / 1회차(=control 최종).
  main_9.json의 Rotated LoRA(1판)는 주 비교에서 제외하고 그 이유를 기록한다 (규칙이 달랐고 최초 코드도 다르다)
- 본 평가(2026-11-01) 코드와 판정은 쓰지 않는다 — 다른 생성 코드다

논문별 검사 대상 (체크리스트를 정답으로 쓰지 않는다 — 원문 식·정의를 인용해 기대값을 유도한다)
- AVQ: attention이 실제로 소비하는 부모 집계값(합·개수). 입력: 같은 부모에 남는 키와 자식으로 이동하는 키를 함께 두고, 합과 평균이 다른 값.
  고의 오답: 자식으로 간 키를 부모 집계에서 제외
- Explicit Dropout: FFN 두 번째 선형층의 정규화 항 (그 층의 실제 입력으로 만든 Gram 사용). 입력: d ≠ hidden, 토큰 2개 이상.
  Gram 정규화(토큰 수로 나누는지 등)는 원문 정의를 먼저 인용해 정한다. 원문이 정하지 않으면 '판단 불가 항목'으로 두고 그 부분은 비교하지 않는다.
  고의 오답: 두 번째 층에 첫 번째 층 입력의 Gram 사용
- Rotated LoRA: R2 리만 기울기 성분 (S, Up, Vp) 하나로 좁힌다 — 전체 옵티마이저 1회 갱신은 하지 않는다.
  입력: 영 기울기가 나오지 않는 G, 직교 U·V 고정. 고의 오답: Sᵀ 대신 S 사용, Up에서 US 항 누락.
  R3·R5(m×n 행렬을 만들지 않는 계산 방식)는 수치와 무관한 '구조 관찰'로 따로 적는다 — 값이 맞아도 R3·R5 충족이 아니다

사전 등록 (생성 코드를 보기 전에 파일로 고정·커밋)
- 논문별: 원문 인용(쪽·식 번호), 기대값 유도 과정, 고정 입력, 기대값, 허용 오차(예: float64, atol 1e-8)
- 기준 계산은 생성 코드를 보지 않고 작성하고, 손계산 가능한 크기의 예제는 사용자가 숫자를 확인할 수 있게 적는다
- 기준 구현은 통과하고 고의 오답은 실패하는지 확인한 뒤에 생성 코드에 적용한다

어댑터 규칙 (코드를 보는 단계 — 기대값·입력·오차는 바꾸지 않는다)
- 허용: 클래스·함수 이름, 인자, 축 순서 대응, 상태(코드북·할당·가중치 등) 주입, 출력·중간값 추출
- 금지: 빠진 계산을 더하기, Gram 등 검사 대상 값을 어댑터에서 계산하기, 깨진 함수 교체, 기대값·오차 수정
- 연결할 수 없으면 원인을 기록하고 '평가 측 문제로 판단 불가'로 분류한다. 구현을 고쳐서 통과시키지 않는다
- 어댑터 코드도 결과와 함께 저장한다

결과 분류
- 수치 일치 / 수치 불일치 / 대상 코드 실행 불가 / 평가 측 문제로 판단 불가 — 분모에서 조용히 빼지 않는다
- 논문별로 보고하고, 입력 여러 개를 독립 표본처럼 세지 않는다

주장할 수 있는 범위 (결과가 나온 뒤)
- "알려진 문제 사례로 고른 3편의 저장된 코드에서, 사전 고정한 입력과 독립 기준 계산으로 핵심 계산 하나씩을 비교했다.
  exec 최종본 ○건 일치. control·최초본은 실행 불가로 비교하지 못했다. 일부 표본은 검사 규칙 변경 후 재생성한 코드다"
- 논문 전체 구현, 학습 성능, 효율(구조) 요구사항, 새 논문에서의 일반적 정확성 향상은 입증하지 않는다

실행: 로컬 Docker(#60 이미지) 또는 E2B. LLM 호출 없음. 기록: eval-results/2026-11-accuracy-ref/
범위 밖(후속): 새 논문·반복 생성·같은 예산 비교, 운영 반영, Reviewer 기준 강화

3판에서 바꾼 것 (Codex 재검토 2건)
- 최초본도 실행 여부만 보지 않고 같은 입력·기준값으로 네 가지로 분류한다. 보고 문장은 관측대로 채운다
  (Rotated LoRA는 최초·최종본의 _euclidean_grad_to_tangent_components AST가 같다 — Claude가 원자료로 확인. 최초본의 기존 오류는 다른 함수다)
- "생성 코드를 보기 전 사전 등록"이 아니라: 대상 코드와 알려진 결함을 이미 확인한 상태의 탐색적 평가이며,
  새 수치 평가를 실행하기 전에 원문 기반 기대값·입력·허용 오차를 고정한다

Codex 검토 원문은 세션 임시 폴더에 있었다 (저장소에 넣지 않음). 지적 요지는 위 반영 내용과 같다.
