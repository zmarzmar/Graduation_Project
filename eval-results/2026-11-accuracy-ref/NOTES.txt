논문별 내용
- Rotated LoRA: 손계산 입력과 무작위 직교 입력 모두 일치. 검사한 함수(_euclidean_grad_to_tangent_components)는 최초본과 최종본의 AST가 같다 —
  실행 피드백이 고친 것은 다른 함수(_conditioning_frame의 정의 안 된 변수 V)다. 이 계산이 맞은 것은 실행 검사 덕분이 아니다.
  구조 관찰(수치와 별개): 이 함수는 GV = grad_outputᵀ(xV), GᵀU = xᵀ(grad_output U)로 m×n 기울기를 만들지 않는다(R3 방식). R5는 보지 않았다
- AVQ: 두 판 모두 부모 집계에서 자식으로 간 키를 뺀다. 손계산 입력에서 부모0 = (1,2) n=1, 부모1 = (7,11) n=1 (기대값 (4,7) n=2, (20,28) n=2).
  자식 집계는 맞다. 결과가 고의 오답 '부모에서 자식으로 간 키 제외'와 같다. 실행 피드백은 배치 차원 모양 오류를 고쳤고 이 계산은 그대로다.
  한계(SPEC 2절): 다른 집계로 최종 attention을 같게 만드는 구현이 있을 수 있다 — 이번에는 집계 정의(알고리즘 1)와의 일치만 봤다
- Explicit Dropout: 최초본은 2층 정규화에 1층 입력의 Gram을 써서 d ≠ h에서 einsum 차원 오류(본 평가 D6, #60 1회차와 같은 결함).
  최종본은 층마다 자기 입력을 쓴다(꺼낸 입력 모양 [4,3], [4,5] — 고쳐졌다). 그러나 값이 기준의 정확히 0.25배 = 1/토큰수(4):
  _empirical_gram이 XᵀX를 토큰 수로 나눈다. 사전 등록대로 판정은 '수치 불일치', 진단은 '스케일만 다름(1/토큰수)'.
  원문은 XᵀX를 토큰에 대해 합한다(식 4·13의 평균은 에폭·마스크 평균). 원문 해석이 들어간 부분이다 — SPEC 2절

정리
- exec 최종본 3개 중 원문 기준과 수치가 맞은 것은 1개(Rotated LoRA R2)이고, 그것은 최초본부터 맞았다
- 실행 피드백은 세 코드를 모두 실행되게 했고(#60), Explicit Dropout에서는 층별 입력이라는 구조 결함까지 고쳤다(실행 불가 → 스케일만 다름).
  AVQ의 집계 결함은 실행 오류가 아니라서 실행 검사로 드러나지 않았고 그대로 남았다
- 주장할 수 있는 것 (SPEC 7절): "알려진 문제 사례로 고른 3편의 저장된 코드에서, 사전 고정한 입력과 원문 기반 기준 계산으로 핵심 계산 하나씩을 비교했다.
  최초본은 일치 1·불일치 1·실행 불가 1, exec 최종본은 일치 1·불일치 2(그중 1개는 1/토큰수 스케일 차이). 일부 표본은 검사 규칙 변경 후 재생성한 코드다(Rotated LoRA)."
- 이 3편에서 실행 검사가 '논문대로 계산하는 정도'를 높였다는 근거는 없다. 실행되게 만든 것과 논문대로 계산하는 것은 별개였다

실행 중 고친 것 (기대값·입력·오차·분류는 바꾸지 않았다)
- 1차 실행에서 run_targets.py가 대상 코드를 sys.modules에 등록하지 않아, @dataclass가 있는 4개(Rotated LoRA·AVQ 두 판)가 불러오기 단계에서
  "'NoneType' object has no attribute '__dict__'"로 멈췄다 — 평가 측 결함이다. #60 runner처럼 모듈로 등록하도록 고쳐 다시 돌렸다.
  Explicit Dropout 두 판의 1차 결과는 2차와 같았다

한계
- 3편 × 계산 1개 × 저장된 코드 1회분. 알려진 문제 사례를 골랐다 (선택 편향). 논문별 결과이고 합산하지 않는다
- 기준 계산·손계산·원문 해석은 Claude가 했다. 손계산 숫자는 SPEC.txt에 있어 사람이 확인할 수 있다 — 사용자 확인 전이다
- 논문 전체 구현, 학습 성능, 효율 요구사항, 새 논문에서의 일반화는 보지 않았다
